# AGENTS.md

Guidance for humans and coding agents working on gutterglow.nvim.

## Purpose

Color the cursor line number (`CursorLineNr`) according to the current mode. Nothing else.

## Specification

- Target: Neovim >= 0.12 only. No backward compatibility shims.
- No runtime dependencies. lualine.nvim is optional.
- Activation: only via `require('gutterglow').setup(opts)`. No `plugin/` autoload.
- Color source priority per mode:
  1. lualine theme `theme[mode][section]` (fg, bg, bold/italic from `gui`) if lualine loads and `lualine.enabled = true` (default).
  2. `modes[mode]` from config: `nvim_set_hl()` spec or highlight group name (copied, links resolved); `'CursorLineNr'` = original snapshot. Defaults: Nvim palette, fg `NvimDarkGrey1`, bg `NvimLight{Blue,Green,Magenta,Magenta,Red,Yellow,Cyan}` for normal..terminal, bold.
- Config merge: deep merge, except each `modes[mode]` the user sets replaces that default whole.
- lualine fallbacks: `select` -> `visual` -> `normal`; any missing mode -> `normal`.
- Mechanism:
  - One group per mode: `Gutterglow<Mode>` (e.g. `GutterglowInsert`), always redefined from the resolved source.
  - `CursorLineNr` is linked to the current mode's group on `ModeChanged`.
  - The original `CursorLineNr` is snapshotted on enable and `ColorScheme`; `disable()` restores it.
  - Colors are re-resolved on enable, `VimEnter` (lualine may be set up later) and `ColorScheme`.
- Mode mapping (first char of `nvim_get_mode().mode`): `n`/`nt` normal, `i` insert, `v V ^V` visual, `s S ^S` select, `R` replace, `c` command, `t` terminal, else normal.
- Public API: `setup`, `enable`, `disable`, `toggle`, `refresh`; command `:Gutterglow {enable|disable|toggle|refresh}`.
- Health: `:checkhealth gutterglow` checks options, setup and lualine state.

## Layout

```
lua/gutterglow/init.lua      API, autocmds, mode -> group linking
lua/gutterglow/config.lua    defaults, types, validation
lua/gutterglow/lualine.lua   lualine theme lookup
lua/gutterglow/health.lua    :checkhealth
tests/minimal_init.lua       test bootstrap
tests/test_gutterglow.lua    mini.test cases
tests/fixtures/lualine/      lualine stub with a table theme
```

## Conventions

- Keep it small; prefer deleting code over adding options.
- No globals; module-local state only. Use `vim.api`, `vim.validate`, `vim.tbl_deep_extend`.
- Annotate with LuaCATS (`---@class gutterglow.*`, `---@param`, `---@return`).
- Format with stylua (`.stylua.toml`: 2 spaces, single quotes, width 100). CI runs `stylua --check .`.
- Conventional commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).

## Testing

- Framework: mini.test with a child Neovim per case. `make test` clones mini.nvim into `deps/`.
- Every behavior change needs a test. lualine is tested via the stub in `tests/fixtures/lualine`.
- Verify rendering with `screenattr()` rather than screenshot attr codes, which are renumbered per screenshot.

## Docs

- `README.md` is the single source of documentation; keep its section structure.
- `doc/gutterglow.txt` is generated by panvimdoc in CI on `main`; never edit by hand.
- Update README and this file when options, API or behavior change.
